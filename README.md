# diode-editor.github.io

Сайт Diode и **курируемый реестр расширений**, который раздаётся отсюда же через GitHub Pages.

```
index.html                          сайт
benchmarks/index.html               страница бенчмарков: читает ветку bench-data репозитория diode
extensions/<publisher>.<name>.json  ИСТОЧНИК ПРАВДЫ реестра — PR-ы сюда
artifacts/<id>-<version>.vsix       байты ТОЛЬКО наших собственных расширений
registry/v1/index.json              СГЕНЕРИРОВАНО — руками не трогать
registry/v1/meta/<id>.json          СГЕНЕРИРОВАНО — руками не трогать
scripts/registry.mjs                валидатор и сборщик
```

Публичные адреса:

- `https://diode-editor.github.io/registry/v1/index.json` — список для поиска и Extensions view;
- `https://diode-editor.github.io/registry/v1/meta/<id>.json` — карточка расширения.

`v1` в пути — версия схемы. Ломающая смена формата встанет рядом как `v2`, а уже выпущенные
редакторы продолжат читать `v1`.

## Курируемость

В реестр попадает только то, что мы проверили в Diode: расширение заводится через extension host
и его ключевые сценарии проходят. Для стока из Open VSX (`kind: "proxy-openvsx"`) это значит, что
запинена **конкретная** версия — URL плюс `sha256`; байты остаются у автора, мы их не перехостим.
Сток, которого на Open VSX нет (`kind: "proxy-hosted"`), перевыкладывается немодифицированным
`.vsix` в `artifacts/` — только если его лицензия разрешает редистрибуцию (фиксируется в поле
`license`); пин тот же — конкретная версия плюс `sha256`. Свои расширения (`kind: "native"`)
тоже лежат в `artifacts/`.

Опубликованная версия неизменна. Обновление — это **добавление** новой записи в `versions`, а не
правка существующей: клиенты уже запинили `sha256`, и подмена артефакта под тем же номером — ровно
то, от чего пин защищает. CI отказывает в правке и удалении опубликованных версий.

**Только релизы — pre-release в реестр не попадает.** Клиент берёт максимальную по semver совместимую
версию и ставит её всем, а pre-release-сборку сам автор готовой не считает. По номеру её часто не
распознать: у `redhat.java` pre-release-канал — это `1.57.2026092608`, валидный релизный semver и
больше последнего релиза `1.56.0`; так он однажды и попал в реестр. Поэтому запрет двойной:
номер с semver-суффиксом (`1.2.0-beta`) отвергается всегда, а `--fetch` открывает сам `.vsix` и
отвергает артефакт с флагом `Microsoft.VisualStudio.Code.PreRelease` в `extension.vsixmanifest`.
Заодно `--fetch` сверяет с записью `publisher.name` и `version` из `extension/package.json` и
`targetPlatform` из манифеста. Просочившийся pre-release снимается удалением его записей — это
единственное удаление, которое CI пропускает без `--allow-removals`, и то после того, как сам
скачал артефакт и увидел флаг. На Open VSX флаг виден и до скачивания: поле `preRelease` в
`https://open-vsx.org/api/-/query?extensionId=<id>&includeAllVersions=true`.

## Как добавить расширение

1. Создать `extensions/<publisher>.<name>.json`. Имя файла — первичный ключ и обязано совпадать с
   полем `id`, а `id` — с `publisher.name` **из манифеста расширения** (регистр значим: при
   установке Diode сверяет id с манифестом побайтно).
2. Заполнить запись версии: `version` (только релиз — см. выше), `engines` (хотя бы одно из `diode`/`vscode`, валидный
   semver-диапазон), `artifact` (`https`, разрешённый хост), `sha256` (64 hex в нижнем регистре),
   опционально `size` и `publishedAt`.
3. Если в Diode работает не всё — добавить пометку `support`:
   ```json
   "support": {
       "level": "partial",
       "works": ["Что работает — коротким пунктом"],
       "limits": ["Что не работает и почему"]
   }
   ```
   `level: "partial"` требует непустого `limits`: пометка без объяснения ничего не сообщает.
   Пометка едет и в `index.json` — бейдж `Partial` виден в списке до установки, а на странице
   расширения разворачивается в два списка. Типичный повод — webview: языковая часть расширения
   работает, панель не открывается (`Supermaven.supermaven`).
4. Проверить локально:
   ```sh
   npm ci
   node scripts/registry.mjs validate --fetch
   ```
   `--fetch` реально скачивает артефакт и сверяет `sha256` и `size` — то есть проверяет пин, а не
   его переписанную копию, — и открывает его манифест: pre-release-сборка и артефакт не той
   версии или платформы отвергаются.
5. Прислать PR, трогающий только `extensions/` (и `artifacts/`, если расширение наше).
   `registry/v1/**` собирает CI после мержа — в PR этих файлов быть не должно.

Форма записи и её нормативное описание — `src/vs/platform/extensionManagement/common/registryFormat.ts`
в [репозитории редактора](https://github.com/diode-editor/diode). Проверки в `scripts/registry.mjs` —
сознательно упрощённое эхо этого норматива: строже (неизвестные ключи и невалидные диапазоны здесь
фатальны), но описано отдельно, чтобы CI сайта не тащил тулчейн редактора.

## Команды

```sh
node scripts/registry.mjs validate [--base <ref>] [--fetch] [--allow-removals]
node scripts/registry.mjs build [--check]
```

`--base <ref>` включает проверку иммутабельности против ветки (в CI — `origin/main`).
`--allow-removals` снимает запрет на удаление версий и расширений — флаг мейнтейнера для аварийного
снятия, не для обычного PR (снятие pre-release его не требует, если включён `--fetch`). `build --check` проверяет, что опубликованный вид соответствует
исходникам, ничего не записывая.
